# 项目管理软件实训 · 练习指引

> 配套案例数据（`data/`）与 Microsoft Project 计划文件使用。建议按顺序完成练习一～七，每个练习后的思考题用于巩固对应知识点。

## 练习一：创建项目文件与 WBS

1. 打开 Microsoft Project，新建空白项目。
2. 设置项目开始日期为 2026-05-11（项目信息 → 开始日期）。
3. 将「任务清单」中的任务名称和 WBS 编码录入软件。
4. 使用「降级」「升级」按钮建立任务层级，形成 WBS 结构。
5. 将汇总任务标记为相应类型，检查 WBS 是否完整覆盖项目范围。

**思考题**：WBS 分解到什么颗粒度最合适？为什么？

## 练习二：建立任务逻辑关系

1. 为所有任务设置工期（取自「任务清单」）。
2. 根据「前置任务」列建立依赖关系（默认为 FS 完成-开始）。
3. 识别哪些任务可设置为 SS（开始-开始）或 FF（完成-完成）关系以缩短工期。
4. 观察甘特图，确认任务逻辑关系是否合理。

**思考题**：如果增加任务间的搭接关系（如 SS+50%），对总工期有什么影响？

## 练习三：关键路径分析

1. 在网络图（Network Diagram）中找出关键路径。
2. 对比「赶工方案」中标注的关键路径任务，判断是否一致。
3. 查看各任务的总时差（Total Slack）与自由时差（Free Slack）。
4. 分析哪些非关键任务时差最大，以及如何利用这些时差。
5. 计算项目总工期，应为 162 个工作日、完工日期 2026-12-22，并与里程碑计划核对。

**思考题**：关键路径上的任务是否可以有自由时差？为什么？

## 练习四：资源分配与资源平衡

1. 将「资源列表」中的资源录入项目资源库。
2. 按「任务清单」的资源名称列为各任务分配资源。
3. 查看资源使用状况（Resource Usage），找出资源过度分配的情况。
4. 使用资源平衡（Resource Leveling）解决过度分配。
5. 观察资源平衡后项目工期和成本的变化。

**思考题**：资源平衡为什么会导致工期延长？有哪些替代方案？

## 练习五：甘特图与跟踪基准

1. 美化甘特图：标识关键路径、里程碑标记、进度线。
2. 设置项目基准计划（Baseline）。
3. 假设项目进行到第 60 个工作日，按以下进度更新：
   - 已完成：第 1、2 阶段全部任务；
   - 进行中：第 3 阶段任务完成 80%，第 4 阶段任务完成 30%；
   - 其余任务尚未开始。
4. 查看跟踪甘特图，比较实际进度与基准计划的差异。
5. 计算挣值指标：PV、EV、AC、SV、CV、SPI、CPI。

**思考题**：如果 SPI < 1 但 CPI > 1，说明什么问题？应采取什么措施？

## 练习六：赶工与工期压缩

1. 假设业主要求项目提前 15 天完工，制定赶工方案。
2. 依据「赶工方案」的成本斜率数据，选择最优赶工组合。
3. 原则：优先压缩关键路径上成本斜率最低的任务。
4. 计算每压缩 1 天的总成本增量，绘制工期-成本曲线。
5. 在 Project 中调整任务工期，验证赶工后关键路径是否变化。

**思考题**：压缩到一定程度后，关键路径会发生什么变化？为什么？

## 练习七：风险分析与应对

1. 识别项目主要风险（至少 10 项），建立风险登记册。
2. 对风险进行概率和影响评估，计算风险等级。
3. 针对高等级风险制定应对策略（规避、转移、减轻、接受）。
4. 设置风险储备（管理储备和应急储备），建议金额为总预算的 10%。
5. 在项目计划中预留缓冲时间（如关键路径末尾增加 3 天缓冲）。

**思考题**：如何在 Project 软件中模拟风险对项目进度的影响？
